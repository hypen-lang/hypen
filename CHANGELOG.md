# Changelog

All notable changes to Hypen will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **Animation API (Layers 1–2)** — Portable `.transition()`, `.enter()`, `.exit()`, and `.layout()` applicators. The engine lowers each into a reserved `__anim.*` prop carrying one JSON object (vocabulary: curves `linear|easeIn|easeOut|easeInOut|spring`, presets `fade|slide|scale`, directions `top|bottom|leading|trailing`) and filters `.transition(props: [...])` against a cross-renderer animatable whitelist. Exit animations are enabled by a new optional `transition: true` flag on the `Remove` patch: the flagged subtree root is emitted before its descendants' plain Removes so renderers can play the exit and defer teardown; the field is omitted when false, keeping the wire format unchanged for existing renderers. The DOM renderer implements all four channels (CSS transitions, enter/exit presets, FLIP layout moves, reduced-motion snapping, inert exiting subtrees); native renderers ignore the new props/flag and snap (Canvas parity landed separately — see below). See `hypen-web/docs/animation.md`.
- **`.animate()` preset timelines** — Built-in looping/one-shot keyframe presets `pulse`, `spin`, `shimmer`, and `shake` via a fifth animation applicator: `.animate(spin)`, `.animate(pulse, duration: 800, repeat: 3, curve: easeInOut)`. The first positional token names the preset; `duration:`/`delay:` (ms), `repeat:` (`loop` or a positive integer), and `curve:` are named-only modifiers with per-preset defaults filled by the engine. Lowered to the `__anim.animate` prop (`{"preset","duration","repeat","curve"}` plus `"delay"` when given); an unknown preset warns and omits the animation, every other invalid argument falls back to the preset's default. The DOM renderer plays presets via one injected stylesheet (CSS `@keyframes` + per-node CSS custom properties; `shimmer` is a gradient `::after` overlay) and reduced motion disables playback; other renderers ignore the prop and show the node static. Author-defined `animation { }` blocks and a `when:` trigger are deferred — a preset inside an `If` plays when the node enters. See `hypen-web/docs/animation.md`.
- **Canvas renderer animation parity** — The Canvas 2D renderer now plays the `__anim.*` animation channels instead of snapping, via a per-frame numeric ticker (`CanvasAnimator`, `hypen-web/packages/web/src/canvas/anim.ts`) driven by the renderer's own coalescing redraw loop (the engine never ticks; the ticker stands down when the last animation settles). Interpolated values are written into the real node props before layout and hit-testing each frame, and layout-affecting props (width/height/gap/fontSize/padding/margin/borderColor) re-solve layout per tick, so hit targets follow the animated geometry. Supported: `.transition` on numeric whitelist props plus RGBA color interpolation (`color`/`backgroundColor`/`borderColor`; hex, `rgb()`/`rgba()`, basic named colors) with seamless mid-flight retargeting; `.enter` `fade`/`slide`/`scale` (RTL-aware, first-batch and cached-route suppression as on DOM); `.exit` with deferred teardown, immediate hit-test and scroll-target exclusion of the exiting subtree, and finalize on settle or a `duration + delay + 80ms` timeout backbone; `.animate` `pulse`/`spin`/`shake` with DOM-matching keyframe shapes (finite repeats never replay on a cached re-attach). Easing shares the DOM renderer's numeric curve layer, so both renderers trace identical curves. Deliberate canvas snaps: `.layout` FLIP moves (a transform FLIP would desync hit-testing from painted position), `cornerRadius` transitions (canvas paint reads `borderRadius`), and `shimmer` (DOM-only gradient overlay). Reduced motion (live `matchMedia`) snaps everything including immediate exit finalize; unknown or malformed specs are silent no-ops. See the Canvas capability matrix in `hypen-web/docs/animation.md`.

- **`.states { onState(...) }` named visual states (Animation Layer 4 / Option C)** — A node declares named looks selected by one state path: `.states(@state.cardState, transition: spring, duration: 250) { onState(collapsed).width(48).cornerRadius(8) onState(expanded).width(240).cornerRadius(16) }`. The first positional must be a state reference (else the applicator warns and is ignored); `transition:` (curve token), `duration:`/`delay:` (ms) default to `{easeOut, 250, 0}`. Pose applicators reuse the ordinary applicator→prop machinery (`.tw`, directional forms, and variants work per state) with animation applicators, `.bind`, event applicators, and state bindings excluded from poses (warn + drop). At runtime the driving state value is stringified and matched against the labels: the matching pose's props override the node's base chain; an unmatched label falls back to the base values, and pose-only props are removed (absent-key semantics). The engine lowers each overridden key to an internal state-switched value that resolves to plain JSON — pose flips reach renderers as ordinary `SetProp`/`RemoveProp` patches, so **zero renderer changes were needed** and non-animating renderers always show the correct pose. `.states` also synthesizes the node's `__anim.transition` scoped to the overridden animatable props (an explicit `.transition` on the node wins) and ships the active label as the reserved `__anim.states` prop (`{"label": ...}`, `null` in the fallback pose) for completion timing. Malformed entries warn and degrade individually; duplicate labels warn with last-wins. The sketch-era `.inState` chain form and the `stagger:` group envelope remain deferred. The `{ }` block form parses directly from `.hypen` source (see the applicator children blocks entry below). See `hypen-web/docs/animation.md`.
- **Applicator children blocks in the grammar** — The parser now accepts a `{ }` block after any applicator, parsed into `ApplicatorSpecification.children` (which the AST had modeled all along): `.states(@state.cardState, transition: spring) { onState(collapsed).size(48) onState(expanded).size(240) }` parses directly from `.hypen` source. The production is generic, not special-cased to `.states`: whitespace/newlines/comments are allowed between `)` and `{` exactly as for component children blocks; block entries are full recursive component specifications (their own applicator chains, nesting, and nested applicator blocks); the applicator chain may continue after a block (`.states(...) { ... }.padding(4)`); and a zero-arg applicator with a block (`.modifier { ... }`) also parses. The LSP document model surfaces applicator-block children when parsing via WASM (the regex fallback does not see them). The animation conformance fixtures now express `.states` inline in `source` — the interim `input.applicators` fold-path escape hatch in the Rust runner has been removed, and the TypeScript-runner skips it forced on the `.states` fixtures are lifted.
- **`.onAnimationComplete()` completion events (Option F)** — `.onAnimationComplete(@actions.animationDone)` dispatches an action when an animation on the node settles **naturally**, enabling module-resident animation state machines without `setTimeout` guesses. It is an ordinary event applicator (zero engine changes; extra named args merge into the payload). Firing points and payloads on the DOM and Canvas renderers: a finite `.animate` preset completing → `{ animation: "<presetName>" }`; `.enter` settling → `{ animation: "enter" }`; `.exit` settling just before teardown → `{ animation: "exit" }`; a `.states` pose transition settling → `{ animation: "states", state: "<matched label>" }`. Interrupted, superseded, and reduced-motion-skipped playbacks fire nothing (removing most completion races by construction); looping presets never complete; `.states` falling back to the default pose fires nothing; nodes without the prop pay zero overhead. Renderers that don't animate (iOS, Android, desktop) never dispatch — completions are motion choreography, not a correctness channel. See `hypen-web/docs/animation.md`.
- **`animate:` transaction-scoped animation (Animation Layer 6 / Option D cheap subset, TypeScript hosts)** — Event applicators accept an `animate:` named argument (`.onClick(@actions.toggleCart, animate: spring)`, or a spec map `animate: {curve: easeOut, duration: 400}`) that animates the *cause* instead of the node: the **first** state flush the action handler produces glides its whitelisted prop changes with that spec on every affected node, `.transition` declared or not, while state changes the action didn't cause (websocket refreshes, timers) keep snapping — SwiftUI's `withAnimation` semantics on Hypen's dispatch pipeline. Mutations after an `await` are unstamped (the stamp clears one microtask after the handler's synchronous portion). Engine side, `updateState`/`updateStateSparse` gain an optional trailing `animation` argument (old arities unchanged); a stamped update that dirties nodes emits a `{type: "batchAnimation", spec: {curve, duration}}` patch as the batch's **first** patch (bare curve tokens normalize to full specs engine-side, default 250ms; no patches → no stamp), which unaware renderers ignore — the rest of the batch is wire-identical to an unstamped one. Both web renderers honor the prelude (DOM via scoped CSS transitions restored on settle; Canvas as its tick-interpolation spec) under the precedence rule structural playbacks > transaction > node `.transition` > snap, and reduced motion ignores stamps entirely. The stamp crosses the dispatch boundary under a reserved payload key that `BaseEngine` lifts into `Action.animate`, so module handlers never see it; only the named `animate:` argument is reserved — a payload field named `animate` is user data. `animate:` is TS-host-only for now: Go and Kotlin hosts strip the reserved key (the dispatch works, the flush snaps; see `hypen-golang/CHANGELOG.md`), and UniFFI drops the prelude (mobile snaps, matching the Remove-flag policy — the Go SDK relays it via `Patch.Spec`). The full SDK `animate()` handler block remains a proposal. Contract pinned by a conformance schema entry and a stamped-emission fixture. See `hypen-web/docs/animation.md`.
- **`.sharedElement()` shared-element transitions (Option H, DOM renderer)** — Cross-route visual continuity: tag a node on each of two routes with the same key (`.sharedElement("cover-@{item.id}")`, optionally `curve:`/`duration:`, defaults `{spring, 350ms}`) and on navigation the incoming node FLIPs from the outgoing node's on-screen rect to its natural position — the list-thumbnail-becomes-detail-hero effect. The key is the first positional argument and the one animation argument where state bindings are legal (identity is data: template keys and pure references re-resolve as ordinary `SetProp`s on state change). The engine lowers to two reserved props (`__anim.sharedKey` identity + `__anim.shared` timing) and knows nothing about geometry; the DOM renderer implements the five-step protocol: snapshot outgoing keyed nodes inside the navigation batch's detached subtrees, apply the batch, FLIP matching incoming nodes (inverted translate+scale prepended to the node's base transform, played with the destination node's timing), degrade silently on unmatched or unmeasurable keys (a plain navigation — never an error), and retarget interrupted flights from the current on-screen position. A matched node's own `.enter` is suppressed (one motion, not two); a zero-delta match plays nothing but still suppresses the enter and immediately dispatches the new `{ animation: "sharedElement" }` `.onAnimationComplete` firing point. Keys that match nothing warn once per key in dev. v1 is transform-only continuity — no corner-radius/opacity interpolation or content crossfade, and no overlay proxy. Canvas, iOS, Android, and desktop ignore the props and show a plain navigation. See `hypen-web/docs/animation.md`.

- **`.scrub()` / `.settle()` scrub bindings (Option G, DOM renderer)** — Gesture- and scroll-driven animation between two of a node's `.states` poses, with the per-frame loop resident entirely in the renderer (zero engine traffic while the input is live): `.scrub(from: closed, to: open, axis: y, over: [0, -400]).settle(curve: spring, duration: 300, bind: @state.sheetPhase)` makes a draggable bottom sheet; `source: scroll` (optionally `of:` a named container) makes a collapsing header. `over:` is a *directed* input range `[inputAtProgress0, inputAtProgress1]` — an upward-opening sheet is `[0, -400]` — with `rubberBand:` resistance beyond it (default 0.4). The engine lowers the pair to four reserved props (`__anim.scrub`, `__anim.scrubSettle`, `__anim.scrubBind`, and `__anim.scrubPoses` — both endpoint values materialized per pose-overridden prop, so renderers interpolate without knowing the pose machinery), cross-validated against the node's `.states` labels; any hard violation (unknown label, missing `over:`, missing `.settle(bind:)`, no `.states` block) warns once and the node degrades to plain `.states` behavior. On the DOM renderer, drags claim after ~6px of slop (taps pass through to children untouched), map *relative* to the pose the finger grabbed (an open sheet re-drags from progress 1; a mid-settle sheet is caught where it is), and on release a velocity-projected settle (~100ms sample window, ~150ms projection) animates to the nearest pose and writes the winning label to the bound state path through the `.bind` channel — one ordinary state write the module handles like any other, after which the eventual `.states` flip fires the normal `{ animation: "states" }` completion. Scroll sources track continuously and write only when progress rests at an endpoint (~150ms debounce), with mid-range quiescence conceding deferred engine writes so live data still updates. Engine writes to scrubbed props defer while a gesture owns the node (gesture wins); precedence is scrub > structural playbacks > transaction > node `.transition`. Reduced motion drags normally (direct manipulation is exempt) and settles instantly. DOM-only in v1 — Canvas, iOS, Android, and desktop ignore all four props and the node still shows the correct pose on state changes; multi-touch is treated as noise; an unmatched `of:` name warns once and falls back to the nearest scrollable ancestor. See `hypen-web/docs/animation.md`.
- **Desktop (Vello) renderer full animation parity** — The native desktop renderer now plays the entire `__anim.*` animation channel instead of snapping, reaching parity with the DOM renderer through `DesktopAnimator` (`hypen-renderer-desktop/src/anim.rs`), a tick-based twin of the Canvas animator driven by the window's demand-driven redraw loop (the engine never ticks; the loop re-arms only while animations are in flight and stands down when the last one settles). Every interpolated value — transforms included — is written into the real renderer `Tree` props that Taffy layout, item emission, and hit-testing read, so pointer/wheel/AccessKit/caret targeting follows the animated geometry (constraint #5). Shipped in four stages: (1) **transforms + hit-testing** — `translateX`/`translateY`/`scale`/`rotate` compose as per-item affines consumed by paint AND every hit surface, so `.transition`/`.enter`/`.exit`/`.layout`/`.animate`/`.states` all move honestly (layout-feeding props restyle Taffy every tick, transform props ride the affine post-pass), plus the #146 removal-sibling FLIP; (2) **shared elements** — `.sharedElement` cross-route FLIP over the Router Detach/Attach seam; (3) **completion events** — `.onAnimationComplete` dispatched on natural settle at all five firing points (enter/exit/finite-preset/states/sharedElement); (4) **scrub** — `.scrub`/`.settle` via a renderer-resident `DesktopScrubber` driven off winit pointer/wheel events with zero engine traffic during the gesture. The `batchAnimation` transaction prelude (`animate:`) is honored too — desktop consumes the engine's patch directly, not via UniFFI. Recorded narrowings (source of truth: the `anim.rs` capability matrix): uniform scale only (the affine's single scale factor averages the DOM's independent sx/sy — exact when aspect is preserved); `shimmer` snaps (no gradient-overlay machinery — the one remaining `.animate` no-op); shared elements are transform-only continuity + uniform scale + globally reduced-motion-skipped (no `.motion(essential)` exemption); scrub uses winit's single OS cursor as the pointer-capture equivalent (multi-touch moot) and interpolates only numeric + color pose endpoints; the removal-sibling FLIP snaps when an exit finalizes in the same redraw as a non-empty patch batch (the cached pre-teardown layout is already gone); and reduced motion is gated by `HYPEN_REDUCED_MOTION` + a programmatic setter rather than an OS query. Transform composition follows the DOM/CSS order (translation applied outside scale/rotate — the reference the protocol was designed against), diverging from Canvas's inside-scale composition. See the desktop capability matrix in `hypen-web/docs/animation.md` and the desktop parity note in `hypen-web/docs/animation.md`.
- **UniFFI animation fields surfaced to mobile** — The FFI boundary deliberately dropped the `Remove.transition` flag and the `batchAnimation` prelude, so iOS and Android could never defer removes or honor transaction stamps even once their renderers read `__anim.*` props. The flat `Patch` record gains `transition: bool` and `spec_json: Option<String>` (UniFFI has no arbitrary-JSON type, so the spec crosses the boundary stringified), and `PatchType` gains `BatchAnimation` — all strictly appended, so every existing positional read stays byte-for-byte at its old offset and the enum's existing wire values are untouched. `from_internal` is now total (`-> Self`, not `Option`), so a patch variant can never again be silently dropped at this boundary; bindings regenerated for both platforms. The Kotlin and Swift hosts relay both fields through the Remote-UI wire with omit-when-absent encoding, preserving the serde skip-if-false contract (the wire stays byte-identical when the fields are unset), and the Swift host now strips the reserved `__hypenAnimate` dispatch key before handlers run, matching Go and Kotlin. Host-initiated stamping remains unexposed — `update_state` has no animation parameter over FFI, so mobile hosts can relay engine-raised preludes but not originate one; `animate:` stamping stays TS-host-only.
- **iOS (SwiftUI) renderer daily-driver animation** — The iOS native renderer plays the daily-driver `__anim.*` channels instead of snapping (stage 1, #158): `.transition` glides via a per-element implicit `.animation(_:value:)` whose animation is resolved per patch batch through the normative precedence chain (`structural > transaction > node .transition > snap`); `.enter`/`.exit` play as `opacity`/`offset`/`scale` poses with the full deferred-remove contract (subtree kept alive and in layout, excluded from hit-testing/dispatch/accessibility immediately, finalized on the `duration + delay + 80ms` backbone); `.states` pose flips glide for free through the synthesized transition; `.animate` presets run with the normative timing; the `batchAnimation` prelude is honored at batch head; `.motion(essential)` and reduced motion (`accessibilityReduceMotion`, live) behave as on the web; and `.onAnimationComplete` dispatches at four firing points with DOM payload parity. Curves are the pinned CSS beziers — `spring` is the fixed overshoot bezier, not SwiftUI's physics spring. Recorded narrowings (see the iOS capability matrix in `hypen-web/docs/animation.md`): SwiftUI's implicit animation is view-scoped rather than property-scoped, `shake` is one-sided (autoreversing repeat), settles are timer-derived, and `.layout` FLIP, `.sharedElement`, and `.scrub`/`.settle` stay snapped (stage 2).
- **Android (Compose) renderer daily-driver animation** — The Android native renderer plays the daily-driver `__anim.*` channels instead of snapping (stage 1, #159): `.transition` glides all whitelisted props by writing interpolated values back as animation overrides on the element, so every prop animates through its existing applicator/component (colors interpolate in straight sRGB matching DOM/Canvas — not Compose's Oklab `Color.lerp`); `.enter`/`.exit` play as a single `graphicsLayer` pose (deliberately not `AnimatedVisibility` — the exiting node keeps occupying layout per the shipped contract) with the renderer-owned deferred-remove protocol and four-plane interaction exclusion (pointer, action dispatch, TalkBack semantics, focus/IME); `.states` glides for free; all four `.animate` presets play, `shimmer` included; the `batchAnimation` prelude is honored at batch index 0 only; reduced motion gates on `Settings.Global.ANIMATOR_DURATION_SCALE` with a live `ContentObserver`, with `.motion(essential)` exempting per node; and `.onAnimationComplete` dispatches at four firing points on natural settle only. Curves are pinned `CubicBezierEasing` instances — `spring` is the fixed overshoot bezier, never Compose's physics `spring()`. Recorded narrowings (see the Android capability matrix in `hypen-web/docs/animation.md` and `hypen-renderer-android/ANIMATION.md`): `.layout` is parsed and deliberately snapped (`Modifier.animateItem` needs Lazy containers; `LookaheadScope` is roadmap), and `.sharedElement` and `.scrub`/`.settle` remain stage 2.
- **Drag and drop (v1)** — Direct manipulation as declarative intent: four role applicators `.draggable(group:, payload:, handle:, activation:, enabled:)`, `.dropZone(group:, id:, enabled:, band:)`, `.sortable(group:, axis:)`, and `.pinboard(group:, x:, y:, grid:, bounds:, units:)`, the existing `.bind(@state.path)` as the write target on a sortable/pinboard, six ordinary event applicators `.onDragStart` / `.onDragOver(dwell:)` / `.onDrop` / `.onSort` / `.onPin` / `.onDragEnd` sharing one payload `{ item, payload?, from: {zone, index}, to: {zone, index}, x?, y?, dropped? }`, and header-less `.states { onState(lifted)… onState(over)… }` blocks whose labels the renderer drives during the drag. Identity is the `ForEach` key — `.draggable()` takes no id. The engine (`ir/dnd.rs`) lowers roles to reserved `__dnd.*` props (`__dnd.source`/`sourcePayload`/`sourceEnabled`/`key`, `__dnd.zone`/`zoneId`/`zoneEnabled`, `__dnd.sort`, `__dnd.pin`/`pinGroup`; static specs as one JSON object, bindable pieces split so they re-resolve as `SetProp`), stamps `__dnd.key` on every draggable in a row, and for reserved-mode pinboards injects `translateX.0`/`translateY.0` bindings to the module-scoped `__dnd.<group>.<key>.{x,y}` state (explicit `null` when unset — renderers treat it as 0); header-less `.states` ships `__anim.states {label: null, runtime: true}` plus `__anim.statePoses` keyed by lowered prop keys. No new `Patch` variants. Malformed args warn once and fall back (named-only arguments; unknown tokens → defaults; `band` out of range → 0.5; a reserved-mode pinboard with no group lowers nothing). Drops are semantic outcomes applied host-side through tracked state: `__hypen_reorder {fromPath, from, toPath, to}` (or `{path, from, to}`) runs the new `portable::path_move` (`to` = final index clamped after removal; nested tree destinations re-addressed; UniFFI `portable_path_move`, wasm `pathMove`, WASI `hypen_portable_path_move`, all returning `{json, moved}`) and `__hypen_pin {path, x, y, xKey, yKey}` sets both fields in one flush — registered next to `__hypen_bind` in the TypeScript, Kotlin, Swift, and Go SDKs; `@hypen-space/core/dnd` exports the constants, parsers, `resolveBand`, `snapToGrid`, `applyPathMove`, and the pure `KeyboardDragMachine`. Typed hosts (Kotlin, Swift) now preserve top-level `__` keys across the typed round-trip and warn once per path the typed encoding drops. Renderers run the drag locally with zero engine traffic until the drop (precedence `dnd > scrub > structural playbacks > transaction > .transition`; engine transform writes to the lifted node defer — on the DOM every transform-kind `SetProp`/`RemoveProp`, elsewhere the translate `SetProp`s; writes to shifted siblings are not deferred; a `Remove`/`Detach` mid-drag cancels with no dispatch; local transforms hold until the engine's `Move` lands or 500ms): the DOM renderer implements the full contract (mouse slop / touch cross-axis slop / 300ms press activation, FLIP-style sibling shifts, the 25/50/25 band rule for a zone on a sortable item, both pinboard modes, `lifted`/`over` poses, and the keyboard path — Space lifts, arrows/Tab move, Space drops, Esc cancels — with `aria-grabbed` and a live region); Canvas 2D (mouse-only, keyboard via the focus manager with `aria-grabbed` mirrored but no live-region announcements; its hit-test now honors `translateX`/`translateY`), desktop (mouse-only, no keyboard, poses snap), iOS (`DragGesture`/`LongPressGesture` activation; no keyboard; not compiled here), and Android (`awaitEachGesture` activation, TalkBack "Move up/down" custom actions in place of keyboard drag, poses snap; not compiled here) reach pointer parity with recorded narrowings. Conformance: twelve lowering fixtures plus `path-move.json` in `engine-compatibility-tests/fixtures/dnd/`, replayed by the engine crate and every host with a fixture harness. Known v1 limits: no OS-level file drags, multi-select, nested sortables, or autoscroll; pinboard items are not keyboard-liftable; `.draggable(handle:)` is accepted and carried in `__dnd.source` but read by no renderer — the lift surface is always the `.draggable` node's own subtree, so the grip pattern is `.draggable()` on the grip; on TypeScript multi-module apps the reserved writes land in the last-constructed module. See `hypen-web/docs/dnd.md` and the guide page `hypen-docs/content/docs/guide/drag-and-drop.mdx`.

### Added
- **`HypenApp` embeds in the desktop browser** — hypen-browser now implements the `HypenApp("wss://…")` embed component, closing the one renderer gap (web, iOS, and Android already had `hypenapp` handlers; the desktop renderer had none, so the home-screen launcher's app tiles opened onto a splash that showed both the loading *and* error slots forever and never connected). A `HypenApp` create in any streamed tree — a tab's or a parent embed's, nesting capped at 4 — spawns its own `RemoteModule` under an `e<n>:` id prefix, re-roots the embedded app's tree onto the host node with the same rewrite tabs use, and toggles the host-owned `.slot("loading")` / `.slot("error")` children through the Router cache's `Detach`/`Attach` patches (loading until the first patch batch, error on terminal connection failure, neither while the embedded tree is live). Because the desktop dispatch path carries no node identity, action references inside the embedded tree are rewritten to carry the embed marker (`@play` → `@e3:play`, `@router.push` → `@e3:router.push`, bind paths likewise), which `BrowserModule::dispatch_action` strips and routes to the embed's remote — verified end-to-end under Xvfb with the real home-screen launcher embedding the live Hypeflix worker, including action round-trips. Lifecycle mirrors the web component: a Router `Detach` (cached route) keeps the connection warm, a real `Remove` or closing the owning tab tears the embed down (transitively for nested embeds), and a reconnect's fresh root replaces the old tree instead of stacking.

### Fixed
- **Value-map applicator variants were emitted in random order** — `.padding({default: 8, md: 16, lg: 24})` lowered its map straight out of the parser's `HashMap`, whose iteration order is arbitrary and reseeded per process, so the engine emitted `padding@lg.0` before `padding@md.0` about as often as not. That is invisible to renderers which resolve variants through the precedence table, but the DOM renderer leans on the CSS cascade: it appends one equal-specificity `@media` rule per variant and lets the last match win, so on a 1024px window `md` beat `lg` whenever the emit order happened to invert — differently on each engine boot. The engine now sorts value-map keys into canonical precedence order (`default`, then breakpoints by ascending min-width, then `disabled` < `hover` < `focus` < `active`) before inserting them, via a new `portable::variant::variant_token_rank`. Explicitly-written variant props (`padding@md.0` from `.tw()` or a host) were never affected.
- **Desktop renderer dropped layered `background` shorthands and every `radial-gradient`** — The desktop renderer's gradient path only read a lone `linear-gradient(...)` out of `backgroundImage`, so a `.background(...)` carrying a CSS layer stack (`radial-gradient(sheen), linear-gradient(brand)` — the home-screen example's icon tiles) painted nothing but its border, gradient wallpaper presets rendered black, and radial gradients (the splash glows, the `.radialGradient()` applicator) were unsupported everywhere. `style.rs` now parses the full `background` / `background-image` layer model into a `ParsedBackground` (solid colour + interleaved image/gradient layers, declaration order reversed to paint order — matching the mobile renderers' `CssBackground`), including a CSS `radial-gradient()` parser with shape/extent/position prelude support (`circle at 24% 14%`, explicit `85% 60%` radii, the four corner/side extent keywords). The Vello painter stacks the layers bottom-up and fills radial gradients on the GPU, stretching elliptical ending shapes with a brush transform. Single-layer linear gradients and lone `url(...)` values keep their existing (tested) fast paths.
- **Desktop `.states` completion settle used the wrong `__anim.states` shape** — The engine lowers the active pose label as a `StateSwitch` object (`{"label": "<label>"}`), but the desktop animator read `__anim.states` as a bare string, so the completion-settle window never opened for real apps and `{ animation: "states", state }` completions never fired. The animator now reads the label through `parse_states_label` (the object's `label` field, with a bare string still tolerated for Remote-UI passthrough), so pose flips open the settle window and dispatch their completion like the web renderers.
- **Desktop scrub stranded on window focus loss mid-drag** — A claimed scrub drag has no OS pointer capture on desktop (winit exposes none), so a `Focused(false)` mid-drag left the gesture stranded: `active_pointer` stayed set (blocking every future gesture until an unrelated release consumed it), the node held its mid-drag pose, and engine writes to its scrubbed keys deferred indefinitely (the redraw ticker is not armed during a drag, so it could never self-heal). Window focus loss is now routed to the scrubber's pointer-up settle path — the winit analog of the DOM's `pointercancel` — settling the drag, dispatching its bind write, and releasing ownership; a pending below-slop drag is discarded.
- **Scrub interaction-lifecycle hardening (adversarial review)** — Twelve confirmed findings fixed pre-release, pinned by 19 regression tests. The root defect both reviewers found independently: drags anchored at progress 0, so grabbing an open sheet snapped it closed — drag mapping is now relative (`p = pAtGrab + travel/span`) with the anchor seeded from the engine's `__anim.states` label, so second drags, grabs mid-settle, to-pose starts, and offset `over:` ranges all continue from where the element actually is. Gesture claim is gated by a ~6px axis slop, so taps no longer steal child clicks or fire bind writes (grabbing a mid-settle element claims immediately — a recorded deviation, since a frozen settle could not survive a no-op release); only the claiming pointer's events drive the drag; release velocity discards samples older than ~100ms so a drag-hold-release projects nothing stale. Ownership now always releases: invalid channel reconfigures run full cleanup, a route detach cancels every scrub source in the subtree (re-armed on re-attach), scroll-source deferral is bounded by ~150ms of quiescence — deferred engine writes concede mid-rest, so a collapsing header can no longer dead-lock sibling updates — and exit-flagged removes cancel the scrub before any exit playback, so a dead interaction never writes state. Also fixed: static base transforms now compose through drags instead of vanishing; `.animate` presets suspend under scrub per the precedence rule (a running CSS animation would beat the scrub's inline styles) and resume at cleanup; the post-settle cleanup handshake completes on *any* `__anim.states` label (a raced different label no longer holds stale visuals until the timeout); and the `>= 0.5` settle tie-break is pinned by test.
- **Transaction-animation hardening (adversarial review)** — Confirmed findings fixed pre-release, pinned by 22 regression tests. Renderer: structural playbacks (enter/exit/FLIP/shared-element) now outrank transaction stamps — a stamped batch can no longer freeze a mid-enter preset or corrupt a shared flight's pinned transform-origin; legacy string `.transition("...")` inline styling is captured on first touch and restored verbatim after a transaction glide; the transaction's `transition-property` is scoped to exactly the props the stamped batch wrote (never the whole whitelist), and an unstamped follow-up write to a still-gliding prop restores the base transition and snaps immediately — the websocket-refresh guarantee holds mid-glide; the Canvas animator skips the transaction's rewind-to-previous for nodes created in the same batch (their queued enter owns the first motion); the stamp is honored only as a batch's first patch, and the remote session's initialTree accumulation drops `batchAnimation` preludes so replays are never over-scoped. Dispatch: the pending stamp uses per-dispatch token identity (two dispatches stamping the same curve string can no longer clear each other); dispatch entry synchronously drains pre-queued observable flushes so a stamp can never land on mutations the action didn't cause; the reserved cross-boundary payload key is stripped in the Go and Kotlin hosts before module handlers run; and the named `animate:` argument is extracted before positional-payload merging, so user payload data named `animate` survives untouched. Go dispatch-side stamping was evaluated and declined with recorded reasons (synchronous per-mutation notify, envelope-less full-patch WASI state path) — `animate:` is documented as TS-host-only in `hypen-golang/CHANGELOG.md`.
- **Shared-element FLIP hardening (adversarial review)** — Seven confirmed findings fixed pre-release: the browser barrel now exports the shared-element and `.states` animation vocabulary (previously typechecked but undefined at runtime); an in-flight shared FLIP's pinned `transform-origin` is cleared on every superseding playback path (enter, exit, `.layout` FLIP, forget, reset), not only the flight's own settle; the FLIP invert now PREPENDS the base transform so nodes with non-identity base transforms (`.states` scale poses, transform applicators) compose in viewport space — the same fix was applied to the pre-existing `.layout` FLIP, which shared the bug; snapshot sources are restricted to nodes under the batch's detach roots, so a persistent app-shell node sharing a key can no longer shadow the real outgoing source or animate out of a still-visible element; the unmatched-key dev warning fires at the default log level, once per key; per-batch snapshot state clears at the start of the pre-pass so a batch that throws mid-apply cannot leak stale snapshots into the next navigation; and zero-delta matches dispatch their completion event instead of swallowing it. Eleven regression tests pin the lot.
- **Legacy single-argument `updateState()` now throws instead of corrupting WASM memory** — Calling the removed `updateState(state)` form passed the state object across the WASM boundary as the scope string, causing an out-of-bounds access in `passStringToWasm0` and a hard tab crash in Chromium. `BaseEngine.updateState(scope, statePatch)` now throws a clear `TypeError` before touching WASM when `scope` is neither a string nor `null`. The playground — the remaining legacy caller, found during real-browser verification of the animation system — was updated to the two-argument `updateState(null, state)` form.
- **Android Remote-UI parser lost whole batches on unknown patch types** — The Moshi parser registered an unknown-enum fallback of `null` for the non-null `Patch.type`, so an unrecognized `batchAnimation` prelude threw and `parseMessage`'s blanket catch discarded the entire patch batch: a TS-hosted app sending a transaction-stamped batch to an Android client silently lost every patch in it, not just the prelude. Adding the enum entry fixes the data loss independent of animation support.

### Deprecated
- The web-only CSS string form `.transition("opacity 0.3s ease")`. It still works on the DOM renderer but logs a deprecation warning; use the portable `.transition(duration:, curve:, props:)` form instead.

### Changed
- **Engine: dependency graph prunes dead paths on unmount** — `DependencyGraph::remove_node` now drops a state path from the dependencies map and the prefix index when its last subscriber goes away. Previously every binding path ever mounted stayed behind as an empty entry, so a long-lived app that keeps mounting rows under fresh `items.<n>.*` paths grew both indexes without bound and every `get_affected_nodes` walked the dead paths.
- **Engine: `set_context` invalidates sparsely** — Replacing a data-source provider's value now diffs it against the previous value (the same portable path diff every SDK uses for state) and schedules only the nodes bound under a changed path, plus any bound to the provider root. A provider refreshed every second that changes one field no longer re-renders every subscriber. The first `set_context` for a provider, and a non-object replacement, still invalidate everything beneath it.
- **DOM renderer: one child-change notification per host per batch** — `onChildrenChanged` is now delivered once to each native host after all of a batch's inserts/moves/removes have landed, instead of synchronously on every patch. A Chart receiving *N* marks through *N* insert patches lays out once rather than *N* times (it used to measure, resolve scales and redraw every mark on each insert). Outside a batch the notification is still synchronous.
- **DOM renderer: text interpolation narrowed to changed paths** — `DOMRenderer.updateState(state, changedPaths?)` indexes `@{state.*}` text bindings by the paths they read and re-interpolates only the bindings a changed path overlaps (parent, child or exact). `HypenModuleInstance.onStateChange` now hands its callback the flushed `StateChange`, and the browser orchestrator passes its paths through, so a keystroke into one field no longer visits every bound text node on the page. Calling `updateState(state)` without paths keeps the full scan.
- **DOM renderer: variant CSS rules are retired when unused** — Rules emitted for `:hover` / `@md` / default-as-rule props are reference-counted per carrying class and deleted from the `hypen-variants` sheet when the last element drops the class (on a value change or when the renderer removes the node). A prop that changes value every frame no longer leaves one dead rule per distinct value in the sheet for the life of the page. The class name now hashes the whole declaration body, so two props sharing a value cannot share a class.
- **Engine: nested state patches look each dependency up once** — Scheduling a batch that records a path and its descendants (`user`, `user.name`, `user.email`, …) now queries the dependency graph for the top-most path only; the descendants are still recorded for the iterable narrowing hint. A nested object patch no longer re-walks the same prefix-index entries once per level.
- **Engine: a dirty node re-resolves only its state-dependent props** — The regular dirty-node render evaluates bindings, template strings and `.states` switches in place and compares only those; a static prop (`Static`, `Action`, `Resource`) resolves identically on every render and is neither cloned nor compared any more. The wholesale rebuild remains for the one case the in-place path cannot order (a previously absent `.states` prop becoming present). Patch output is unchanged.
- **Engine: list items fingerprint structurally** — The iterable memo hashes items by walking the JSON value (raw string bytes, number bits) instead of serializing it into a hasher, removing number formatting and string escaping from the one pass a wholesale array replacement cannot avoid. `cargo bench --bench item_fingerprint` compares the two.
- **Desktop renderer: paint-only refresh is O(affected)** — `refresh_paint_only` runs the opacity and transform post-passes over the affected items only (the classifier already includes every descendant of a patched node), keeps `by_node_id` (the item set is unchanged), rebuilds the positional index lists only when an affected item's membership flipped, and patches the a11y map per id — `SetSemantics` ids now join the affected set — with an order-independent hash. The transform post-pass no longer clones every item id into its rect side-map.
- **Desktop renderer: painter fragments survive structural batches** — A batch the paint-only classifier rejects used to drop every cached scene fragment. It now drops only the fragments that encoded a patched node or one of its descendants (the whole cache still goes when a paint write lands above every scrollable, where it can inherit anywhere), and each survivor re-proves its geometry digest (rects relative to the fragment origin, clips, transforms) against the new layout before replaying — on its next hit, whenever that is. Inserting one post into a long feed re-encodes that card and lets the rest shift. The layout pass itself is still recomputed wholesale on such batches (FLIP needs the fresh miss).
- **Desktop renderer: image loads invalidate only what they can change** — A finished image fetch used to force a full Taffy rebuild and drop every cached paint fragment. Layout now records which decoded sizes each style was built on and rebuilds only when one of those answers flipped (an `Image` with both dimensions set never probes, so its own load does not relayout a feed); the painter keeps per-fragment the sources it drew nothing for and re-encodes only fragments whose awaited source has since decoded.
- **BREAKING:** Removed `IconPack` and all `icons*` registration methods across every SDK. Use `resources(map)` / `resourcesDir(dir)` / `resourcesFile(path)` instead. The Rust engine now owns all SVG parsing; SDKs pass raw SVG strings through `registerResources`. The `@hypen-space/icons-lucide` package, per-SDK SVG parsers, and the UniFFI/WASM/WASI `registerIconPack` / `parse_svg_to_json` / `load_icons_from_dir` entry points have all been removed. The `Icon("name")` / `Icon(@resources.name)` DSL syntax is unchanged.

## [0.4.42] - 2026-03-25

Initial public alpha release of the Hypen cross-platform UI language and engine.

### Added
- **Hypen DSL** — Declarative UI language with components, applicators, modules, state bindings (`@{state.*}`), action dispatching (`@actions.*`), two-way binding (`.bind(@state.*)`) for form elements, and control flow (`ForEach`, `When`, `If`)
- **Parser** — Rust-based parser built on Chumsky combinators, supporting string escaping, nested block comments, arbitrary values, and Tailwind shorthand classes
- **Core Engine** — Rust reactive engine compiled to WASM with IR expansion, path-based dependency tracking, keyed reconciliation/diffing, and minimal patch output
- **Web SDK** — TypeScript packages: `@hypen-space/core` (platform-agnostic runtime with Proxy-based reactive state, router, module system), `@hypen-space/web` (DOM and Canvas renderers), `@hypen-space/server` (Node.js WASM engine, component loader, discovery, RemoteServer), `@hypen-space/web-engine` (browser WASM engine and Hypen orchestrator)
- **CLI** (`@hypen-space/cli`) — `hypen init`, `hypen dev` (hot reload), `hypen build`, and `hypen studio` (preview studio) commands
- **iOS/macOS renderer** (`hypen-swift`) — SwiftUI native renderer with UniFFI bindings
- **Android renderer** (`hypen-renderer-android`) — Jetpack Compose native renderer
- **Kotlin/JVM SDK** (`hypen-kotlin`) — Server-side engine SDK with Kotlin DSL for module definitions
- **Go SDK** (`hypen-golang`) — Server-side engine SDK with Go module system
- **LSP** (`hypen-lsp`) — Language Server Protocol implementation with diagnostics, completion, hover, and formatting
- **Tailwind CSS parser** (`tailwind-parse`) — Rust-based Tailwind class parser for shorthand styling in Hypen components
- **Renderer-agnostic patch protocol** — Unified `Patch` format (Create, SetProp, SetText, Insert, Move, Remove) consumed by all platform renderers
- **Cross-SDK compatibility test suite** — Engine compatibility tests covering Rust, TypeScript, Kotlin, and Go SDKs
- **Component gallery server** — Cross-platform screenshot testing infrastructure
- **Documentation site** — Fumadocs/Next.js docs at docs.hypen.space
- **Example projects** — Including an Instagram clone example with multi-server backends (TypeScript, Kotlin, Go, Rust, Swift)

### Known Limitations
- Canvas renderer is experimental (layout and text features incomplete)
- LSP uses regex-based parser fallback (WASM integration pending)
- `delete` and `in` operators are not reliably tracked by the Proxy-based state system in the TypeScript SDK
- This is an alpha release; APIs may change in future versions
