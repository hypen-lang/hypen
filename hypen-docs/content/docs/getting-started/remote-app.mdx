# Building a Remote App

In this tutorial, you'll build a counter app that runs on your own server and streams its UI to Web and Android clients. This is the recommended approach for production Hypen apps.

## Why Remote Apps?

With remote apps, your server runs the WASM engine and streams UI patches to clients:

```
┌─────────────────────────────────────────────────────┐
│  Your Server (Bun)                                  │
│  • Runs Hypen WASM engine                           │
│  • Manages state and business logic                 │
│  • Streams UI patches over WebSocket                │
└─────────────────────────────────────────────────────┘
                      │ WebSocket
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
   ┌─────────┐   ┌─────────┐   ┌─────────┐
   │   Web   │   │ Android │   │   iOS   │
   │ Browser │   │   App   │   │   App   │
   └─────────┘   └─────────┘   └─────────┘
```

**Benefits:**
- **One codebase** - Write once, run on all platforms
- **Thin clients** - Clients just render patches, no WASM needed
- **Server-side state** - Easy to persist, sync, and secure
- **Hot updates** - Change UI without app store updates

## What We're Building

The same counter from the [first app tutorial](/docs/getting-started/first-app), but streaming to any client:

```
┌─────────────────────────┐
│                         │
│       Count: 0          │
│                         │
│  [ - ]  [Reset]  [ + ]  │
│                         │
└─────────────────────────┘
```

## Step 1: Create the Server

You need [Bun](https://bun.sh) 1.2 or newer. Create a new project:

```bash
mkdir counter-server
cd counter-server
bun init -y
bun add @hypen-space/core @hypen-space/server
```

Create the folder somewhere that is **not inside another JavaScript project**. `bun init` and `bun add` work on the nearest `package.json`, so inside an existing project or workspace they would change that project instead. (`bun init -y` also creates an `index.ts` you won't need.)

Create `server.ts`:

```typescript
import { app } from "@hypen-space/core";
import { RemoteServer } from "@hypen-space/server";

// 1. Define the state
interface CounterState {
  count: number;
}

// 2. Define the module: state, actions and its UI template.
//    `.ui(...)` finishes the definition (no `.build()` needed after it).
const counter = app
  .defineState<CounterState>({ count: 0 })
  .onAction("increment", ({ state }) => { state.count++; })
  .onAction("decrement", ({ state }) => { state.count--; })
  .onAction("reset", ({ state }) => { state.count = 0; })
  .ui(`
    Column {
      Text("Count: @{state.count}")
        .fontSize(48)
        .fontWeight("bold")
        .color("#1F2937")

      Row {
        Button { Text("-").fontSize(24).color("#FFFFFF") }
          .onClick(@actions.decrement)
          .backgroundColor("#EF4444")
          .padding(16)
          .borderRadius(8)

        Button { Text("Reset").color("#FFFFFF") }
          .onClick(@actions.reset)
          .backgroundColor("#6B7280")
          .padding(16)
          .borderRadius(8)

        Button { Text("+").fontSize(24).color("#FFFFFF") }
          .onClick(@actions.increment)
          .backgroundColor("#22C55E")
          .padding(16)
          .borderRadius(8)
      }
      .gap(24)
    }
    .padding(32)
    .gap(24)
    .horizontalAlignment("center")
  `);

// 3. Serve it. Every connected client gets its own Counter instance.
new RemoteServer()
  .module("Counter", counter)
  .onConnection((client) => {
    console.log(`Client connected: ${client.id}`);
  })
  .onDisconnection((client) => {
    console.log(`Client disconnected: ${client.id}`);
  })
  .listen(3000);

console.log("Counter server running on http://localhost:3000 (ws://localhost:3000)");
```

Run the server:

```bash
bun run server.ts
```

The server logs a warning that no `allowedOrigins`/`authenticate` is configured. That's expected during development; see [Security](#security) below.

<Callout type="warn">
`.module(name, def)` picking up the template from `def` needs a `@hypen-space/server` release newer than 0.6.6. On 0.6.6 the server stops with `UI not set`; pass the template to the server as well: `new RemoteServer().module("Counter", counter).ui(template)`.
</Callout>

## Step 2: Connect a Web Client

### Option A: The built-in web client

Open `http://localhost:3000` in a browser. `RemoteServer` serves a small web client at its own address that connects back over WebSocket and renders the app with the DOM renderer. Nothing else is needed.

If the root module's state has a string `location` and its template uses a `Router`, the built-in client also keeps the browser URL in sync: navigation pushes history entries, back/forward work, and deep links like `/counter` open on that route. Turn the built-in client off with `.config({ webClient: false })`.

### Option B: Your own page

For more control, connect with `RemoteEngine` and render with `DOMRenderer` yourself. Install the web renderer next to the server packages:

```bash
bun add @hypen-space/web
```

Create `client.ts`:

```typescript
import { RemoteEngine } from "@hypen-space/core";
import { DOMRenderer } from "@hypen-space/web";

const container = document.getElementById("app")!;
const engine = new RemoteEngine("ws://localhost:3000");

// Pass the engine so the renderer can send clicks back to the server.
const renderer = new DOMRenderer(container, engine);

// Each (re)connection streams a complete tree, so start from a clean slate.
engine.onSessionEstablished(() => renderer.clear());
engine.onPatches((patches) => renderer.applyPatches(patches));

await engine.connect();
```

And `index.html`, which loads it as a module script:

```html
<!DOCTYPE html>
<html>
  <body>
    <div id="app"></div>
    <script type="module" src="./client.ts"></script>
  </body>
</html>
```

Browsers can't load bare package imports or TypeScript directly, so let Bun bundle the page. With the server still running, in a second terminal:

```bash
bun --port=8080 ./index.html
```

Open `http://localhost:8080`. (For a static deployment, `bun build ./index.html --outdir dist` writes the bundled page to `dist/`.)

To draw on a `<canvas>` instead, use `CanvasRenderer` from `@hypen-space/web/canvas` the same way: `new CanvasRenderer(canvasElement, engine)`.

### Option C: Embed it in another Hypen app

A Hypen app rendered in the browser can embed a remote app with the `HypenApp` component:

```hypen
Column {
  Text("My Counter App")
    .fontSize(24)

  HypenApp("ws://localhost:3000")
}
```

## Step 3: Connect an Android Client

In your Android project, add the renderer from Maven Central:

```kotlin
// build.gradle.kts
dependencies {
    implementation("space.hypen:hypen-renderer:0.4.952")
}
```

0.4.952 is the newest published renderer. It is older than the current Hypen packages (0.6.x), so recent renderer fixes are not in it yet.

In your Composable:

```kotlin
import space.hypen.renderer.HypenApp

@Composable
fun CounterScreen() {
    // On the emulator, 10.0.2.2 reaches the host machine.
    // On a physical device, use your machine's LAN IP, or run
    // `adb reverse tcp:3000 tcp:3000` and use ws://localhost:3000.
    HypenApp(
        url = "ws://10.0.2.2:3000",
        modifier = Modifier.fillMaxSize()
    )
}
```

The app needs the `android.permission.INTERNET` permission, and a plain `ws://` URL needs cleartext traffic allowed (for example `android:usesCleartextTraffic="true"` in a debug manifest). The Android app then connects to your server and renders the counter.

To try a server on a device without building an app, `hypen run android --url ws://localhost:3000` installs the Hypen runner app and points it at your server.

## How It Works

1. **Client connects** - WebSocket connection to server
2. **Server sends initial tree** - Full UI tree as patches
3. **Client renders** - Applies patches to native UI (DOM, Compose, etc.)
4. **User interacts** - Clicks a button
5. **Client sends action** - `{ type: "dispatchAction", action: "increment" }`
6. **Server updates state** - `state.count++`
7. **Server sends patch** - Only the changed text node
8. **Client updates** - Applies minimal patch to UI

## Server API Reference

### RemoteServer

```typescript
new RemoteServer()
  .module(name, definition)  // The entry module; its .ui() template is used
  // or .app(hypenApp)       // Serve modules registered on a HypenApp
  // or .source(dir)         // Discover .hypen/.ts components from a folder
  .ui(dslString)            // Optional: override the entry template
  .config({                 // Optional configuration
    port: 3000,
    hostname: "0.0.0.0",
  })
  .onConnection(callback)    // Called when a client connects
  .onDisconnection(callback) // Called when a client disconnects
  .listen(port?)             // Start the server
```

`.module()` is optional with `.app()` or `.source()`. Without it, the entry is the module named `App` if there is one, otherwise the only module. With several modules and none named `App`, the server throws "entry is ambiguous"; name one `App` or call `.module(name, def)`.

Named modules work as the entry too, with or without a `module Counter { ... }` wrapper in the template:

```typescript
import { HypenApp } from "@hypen-space/core";
import { RemoteServer } from "@hypen-space/server";

const myApp = new HypenApp();

myApp.module("Counter")
  .defineState({ count: 0 })
  .onAction("increment", ({ state }) => { state.count++; })
  .ui(`Column { Text("Count: @{state.count}") Button { Text("+") }.onClick(@actions.increment) }`);

new RemoteServer().app(myApp).listen(3000);
```

The server also answers `GET /__hypen__/health` (`{"status":"ok","server":"hypen-remote"}`) and, for loopback requests only, `GET /__hypen__/stats`.

### serve() Helper

For simpler cases, `serve()` configures and starts a `RemoteServer` in one call and resolves to it:

```typescript
import { app } from "@hypen-space/core";
import { serve } from "@hypen-space/server";

const counter = app
  .defineState({ count: 0 })
  .onAction("increment", ({ state }) => { state.count++; })
  .build();

const server = await serve({
  module: counter,
  moduleName: "Counter",
  ui: `Column { Text("Count: @{state.count}") Button { Text("+") }.onClick(@actions.increment) }`,
  port: 3000,
  onConnection: (client) => console.log("Connected:", client.id),
});
console.log(`Listening on ${server.url}`);
```

`module` takes a module finished with `.build()` or `.ui(...)`. If the module carries its own template from `.ui(...)`, leave out the `ui` option. An unfinished builder (no `.build()`) is also accepted and built for you. `moduleName` defaults to `"App"`, and `source: dir` discovers components from a folder.

## Client API Reference

### HypenApp (Web)

In Hypen DSL:
```hypen
HypenApp("ws://localhost:3000")

// Or with options:
HypenApp(
  url: "ws://localhost:3000",
  autoReconnect: true,
  reconnectInterval: 3000
)
```

### HypenApp (Android)

```kotlin
@Composable
fun HypenApp(
    url: String,
    modifier: Modifier = Modifier,
    config: RemoteEngineConfig = RemoteEngineConfig.DEFAULT,
    navigation: NavigationOptions? = null,
    loadingContent: @Composable () -> Unit = { DefaultLoadingContent() },
    errorContent: @Composable (String) -> Unit = { DefaultErrorContent(it) }
)
```

Newer renderer builds (not yet published) add `safeAreaInsets` and `deviceHost` parameters.

### RemoteEngine (Programmatic)

```typescript
const engine = new RemoteEngine(url, {
  autoReconnect: true,        // Auto-reconnect on disconnect (default: true)
  reconnectInterval: 3000,    // Wait 3s before reconnecting
  maxReconnectAttempts: 10    // Give up after 10 attempts
});

engine.onPatches((patches) => { /* handle patches */ });
engine.onStateUpdate((state) => { /* handle state (after subscribeState()) */ });
engine.onConnect(() => { /* connected */ });
engine.onSessionEstablished((info) => { /* a session started or resumed */ });
engine.onDisconnect(() => { /* disconnected */ });
engine.onError((error) => { /* handle error */ });

await engine.connect();
engine.dispatchAction("increment", { amount: 5 });
engine.disconnect();
```

## Production Considerations

### Scaling

Each client gets its own module instance. For state shared across clients, keep it outside the module. Lifecycle handlers receive `(state, context)`:

```typescript
// Shared state outside the module
const globalState = { viewers: 0 };

const counter = app
  .defineState({ count: 0 })
  .onCreated((state, context) => {
    globalState.viewers++;
  })
  .onDestroyed(() => {
    globalState.viewers--;
  })
  .build();
```

### Security

By default any client can connect. In production, restrict browser origins and authenticate connections before the WebSocket upgrade:

```typescript
new RemoteServer()
  .module("Counter", counter)
  .config({
    // Browsers must send one of these Origins.
    allowedOrigins: ["https://app.example.com"],
    // Runs for every upgrade; native clients (no Origin) are admitted
    // only by this check. Return true to admit.
    authenticate: (request) => validateToken(request.headers.get("Authorization")),
  })
  .listen(3000);
```

`validateToken` stands for your own check (a bearer token, cookie or signed query parameter).

### Compression

`RemoteServer.listen()` enables WebSocket `permessage-deflate` by default, because patch streams are JSON and compress well. It's negotiated per connection, so clients that don't offer the extension fall back to uncompressed frames. Opt out with `.config({ compression: false })` when you need to read the raw wire.

### Deployment

Deploy your server to any platform that supports WebSockets and Bun:
- Fly.io
- Railway
- Render
- AWS/GCP/Azure
- Your own VPS
