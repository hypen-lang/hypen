# Your First App

Let's build a simple counter app to learn the basics of Hypen. By the end of this tutorial, you'll understand:

- How to create components
- How to style with applicators
- How to manage state with modules
- How to handle user interactions
- How to move between screens with the router

## What We're Building

A counter with increment and decrement buttons:

```
┌─────────────────────────┐
│                         │
│       Count: 0          │
│                         │
│      [ - ]  [ + ]       │
│                         │
│      Back to Home       │
└─────────────────────────┘
```

## Step 1: Create the Project

You need [Bun](https://bun.sh) 1.2 or newer (see [Installation](/docs/getting-started/installation)). Scaffold a new project with the Hypen CLI:

```bash
bunx @hypen-space/cli init counter-app
cd counter-app
```

Pick **TypeScript** and the **file-based** layout when asked (they are the defaults). Then start the dev server and leave it running:

```bash
bun run dev
```

Open `http://localhost:3000`. The starter app has three modules in `src/components/`:

- `App` is the root module. Its template holds a `Router` that shows `Home` at `/` and `Counter` at `/counter`.
- `Home` is the welcome screen, with a **Go to Counter →** button.
- `Counter` is a counter screen.

In this tutorial you'll rewrite the `Counter` screen from scratch. Because it is already wired into the router, you don't need to touch `App` or `hypen.json`.

## Step 2: Write the Template

Replace the contents of `src/components/Counter/component.hypen` with:

```hypen
module Counter {
    Column {
        Text("Count: @{state.count}")
            .fontSize(48)
            .fontWeight("bold")
            .color("#1F2937")

        Row {
            Button {
                Text("-")
                    .fontSize(24)
                    .color("#FFFFFF")
            }
            .onClick(@actions.decrement)
            .backgroundColor("#EF4444")
            .padding(horizontal: 24, vertical: 12)
            .borderRadius(8)

            Button {
                Text("+")
                    .fontSize(24)
                    .color("#FFFFFF")
            }
            .onClick(@actions.increment)
            .backgroundColor("#22C55E")
            .padding(horizontal: 24, vertical: 12)
            .borderRadius(8)
        }
        .gap(24)

        Button {
            Text("Back to Home")
                .color("#2563EB")
        }
        .onClick(@router.push, to: "/")
        .padding(12)
    }
    .padding(32)
    .gap(24)
    .horizontalAlignment("center")
    .tw("w-full")
}
```

Let's break this down:

### The Module Declaration

```hypen
module Counter {
    // ... UI goes here
}
```

`module` tells Hypen this component has state. The name `Counter` matches the module defined in `component.ts` next to it.

### State Bindings

```hypen
Text("Count: @{state.count}")
```

`@{state.count}` is a **state binding**. It automatically updates when `state.count` changes.

### Actions

```hypen
Button { Text("+") }
    .onClick(@actions.increment)
```

`.onClick(@actions.increment)` is an event applicator that triggers the `increment` action defined in this module.

Actions are scoped to the module whose template uses them: `@actions.increment` here always goes to `Counter`'s handlers. A child screen can't call an action that only its parent handles.

### Navigation

```hypen
Button { Text("Back to Home") }
    .onClick(@router.push, to: "/")
```

`@router.push` is a built-in action that works from any module. It navigates to the `to:` path, and the `Router` in `App` shows the matching `Route`. The browser URL follows along, so back/forward and reloading `/counter` work too. The other router actions are `@router.back`, `@router.forward` and `@router.replace` (with `to:`).

### Layout and Applicators

```hypen
.fontSize(48)
.fontWeight("bold")
.backgroundColor("#EF4444")
```

Applicators style the component. They're chained with dots and applied in order. `.gap(24)` on the `Row` puts 24 pixels between the two buttons, and `.horizontalAlignment("center")` centers the column's children.

`.tw("w-full")` applies a Tailwind class: it makes the page fill the screen width, which keeps it from shrinking to a narrow strip on desktop and Android. Use it on the root of every routed page.

## Step 3: Write the Module

Replace the contents of `src/components/Counter/component.ts` with:

```typescript
import { app } from "@hypen-space/core";

// Define the state shape
interface CounterState {
  count: number;
}

// Create the module. The name must match `module Counter` in the template.
export default app
  .module("Counter")
  // Set initial state
  .defineState<CounterState>({ count: 0 })

  // Handle increment action - receives a context object
  .onAction("increment", ({ state }) => {
    state.count++;
    // State changes sync automatically via Proxy
  })

  // Handle decrement action
  .onAction("decrement", ({ state }) => {
    state.count--;
  })
  .build();
```

Let's break this down:

### Defining State

```typescript
.defineState<CounterState>({ count: 0 })
```

Sets the initial state. The generic `<CounterState>` provides TypeScript type checking.

### Handling Actions

```typescript
.onAction("increment", async ({ action, state, context }) => {
  state.count++;
})
```

- `action` - Contains the action name, payload, and sender
- `state` - The current state (mutable, auto-synced via Proxy)
- `context` - GlobalContext for cross-module communication
- `context.router` - HypenRouter for programmatic navigation, e.g. `context.router?.push("/")`

### Finishing with `.build()`

`.build()` finishes the module definition. In file-based projects the template lives in `component.hypen`, so `.build()` is the last call. (When a module carries its template inline, end with `.ui(template)` instead; see [Building a Remote App](/docs/getting-started/remote-app).)

## Step 4: Run It!

The dev server you started in Step 1 reloads on save. If it isn't running, start it again:

```bash
bun run dev
```

Open `http://localhost:3000` and click **Go to Counter →**, or open `http://localhost:3000/counter` directly. Click the buttons to increment and decrement, then **Back to Home** to return.

Hot reload restarts the modules, so the count goes back to 0 when you save a file.

<Callout type="warn">
Projects created with CLI 0.6.6 or earlier have `Home` and `Counter` buttons that use `@actions.navigate`. Those clicks fail with `invalid scoped UI action`, because only `App` handles `navigate`. Replace them with `.onClick(@router.push, to: "/counter")` and `.onClick(@router.push, to: "/")`. Those versions also don't update the browser URL or open deep links like `/counter`; use the **Go to Counter →** button.
</Callout>

### Preview with Hypen Studio

For a richer development experience, launch [Hypen Studio](/docs/tooling/studio). It is a full in-browser IDE with a code editor, live preview, state inspector, action log and time-travel debugging:

```bash
bun run studio
```

Studio opens at `http://localhost:5173`. You can edit your component and module files in the editor and see the changes in the live preview. Use the state inspector to watch `state.count` update as you click buttons, and the action log to check that each `increment` and `decrement` action fires.

### Preview on Android and iOS

Run your counter app on a device, emulator or simulator:

```bash
# Android (requires adb)
bunx hypen run android

# iOS Simulator (requires Xcode)
bunx hypen run ios
```

The CLI downloads a lightweight runner app, detects your connected devices and launches your app with hot reload. The same Hypen code renders natively on each platform: DOM elements on the web, Jetpack Compose on Android, SwiftUI on iOS.

Combine device preview with Studio to edit in the browser and see the changes on the device:

```bash
bunx hypen run android --studio
bunx hypen run ios --studio
```

## What's Happening

1. **Discovery** - The CLI discovers the modules in `src/components/` and starts from `App`
2. **Parse** - The Hypen engine parses the `.hypen` templates
3. **Routing** - `App`'s `Router` matches the current path (`/counter`) and renders `Counter`
4. **Initial Render** - Creates DOM elements with `count: 0`
5. **Click** - User clicks the "+" button
6. **Action** - `@actions.increment` triggers `Counter`'s action handler
7. **State Update** - `state.count++` modifies the state
8. **Auto-Sync** - State changes are tracked via Proxy and sync automatically
9. **Re-render** - The engine diffs and updates only the text "Count: 1"

## Challenges

Try extending the counter. Each challenge adds a piece to the template and a handler to the module chain (before `.build()`).

### 1. Add a Reset Button

Add a button that sets count back to 0:

```hypen
Button { Text("Reset") }
    .onClick(@actions.reset)
```

```typescript
.onAction("reset", ({ state }) => {
  state.count = 0;
})
```

### 2. Add a Step Size

Let users add different amounts. Extra arguments after the action become its payload:

```hypen
Row {
    Button { Text("+1") }.onClick(@actions.add, step: 1)
    Button { Text("+5") }.onClick(@actions.add, step: 5)
    Button { Text("+10") }.onClick(@actions.add, step: 10)
}
.gap(8)
```

```typescript
.onAction<{ step: number }>("add", ({ action, state }) => {
  state.count += action.payload?.step ?? 1;
})
```

### 3. Prevent Negative Numbers

Change the `decrement` handler:

```typescript
.onAction("decrement", ({ state }) => {
  if (state.count > 0) {
    state.count--;
  }
})
```
