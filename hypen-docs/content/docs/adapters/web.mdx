# Web Adapter

The web adapter (`@hypen-space/web`) renders Hypen UIs in the browser. It has two renderers, **DOM** (native HTML elements) and **Canvas** (2D canvas drawing). Both are pure patch consumers: they apply the patches a Hypen engine produces and send user actions back through `dispatchAction`. Where the patches come from is up to you:

- **A server** (recommended). Modules run in a `RemoteServer` (or `hypen dev`), which streams patches over WebSocket to a `RemoteEngine` in the page.
- **A worker in the page.** `hypen build` produces a static site that runs your modules and the WASM engine in a Web Worker and renders with the DOM renderer.

## Installation

```bash
bun add @hypen-space/core @hypen-space/web
```

Add `@hypen-space/web-engine` only if you run the WASM engine in the browser yourself (see [Browser WASM Engine](#browser-wasm-engine)).

## Quick Start

You may not need to write any client code:

- `hypen dev` and `new RemoteServer()...listen(3000)` serve a built-in web client at `http://localhost:3000`: the `RemoteEngine` + `DOMRenderer` pairing below, with browser URL sync and deep links. See the [TypeScript SDK](/docs/servers/typescript).
- `hypen build` writes a self-contained static site to `dist/` (no CDN at runtime). Serve it with `node dist/server.js` or any static host that falls back to `index.html`.

To embed Hypen in your own page, connect a `RemoteEngine` to a server and hand its patches to a renderer:

```typescript
// main.ts
import { RemoteEngine } from "@hypen-space/core";
import { DOMRenderer } from "@hypen-space/web";

const container = document.getElementById("app")!;
const remote = new RemoteEngine("ws://localhost:3000", {
  autoReconnect: true,
  reconnectInterval: 3000,
  maxReconnectAttempts: 10,
});

// A renderer only needs something with dispatchAction(), which RemoteEngine has.
const renderer = new DOMRenderer(container, remote);

remote.onPatches((patches) => renderer.applyPatches(patches));
remote.onConnect(() => console.log("Connected"));
remote.onDisconnect(() => console.log("Disconnected"));
remote.onError((error) => console.error("Error:", error));

await remote.connect();
```

```html
<!-- index.html -->
<!doctype html>
<html>
  <body>
    <div id="app"></div>
    <script type="module" src="./main.js"></script>
  </body>
</html>
```

Bundle the script for the browser (`bun build main.ts --target browser --outdir .`), serve the folder, and run any Hypen server on port 3000. If the page is served from a different origin than the server and the server sets `allowedOrigins`, add the page's origin to it.

## DOM Renderer

```typescript
new DOMRenderer(
  container: HTMLElement,
  engine: { dispatchAction(name: string, payload?: unknown): void },
  debugConfig?: Partial<DebugConfig>,
  options?: DOMRendererOptions,
)
```

The `engine` argument is where user actions go: a `RemoteEngine`, the browser `Engine` from `@hypen-space/web-engine`, or any object with a `dispatchAction` method. Without it, clicks do nothing.

| Method | Description |
|---|---|
| `applyPatches(patches)` | Apply a patch batch |
| `getNode(id)` | The `HTMLElement` for a node id |
| `clear()` | Remove everything the renderer created |
| `getComponentRegistry()` / `getApplicatorRegistry()` | Extend the renderer (below) |
| `setDebugConfig(config)` / `resetDebugTracking()` / `getDebugStats()` | Re-render heatmap (below) |

`DOMRendererOptions` has `routeFocus` (`"auto"` moves focus to the incoming route on navigation, `"off"` leaves focus alone) and `safeAreaInsets` (override the insets `SafeArea` pads by).

### Debug Heatmap

The DOM renderer includes a re-render heatmap for performance debugging. Elements that re-render frequently glow red:

```typescript
const renderer = new DOMRenderer(container, remote, {
  enabled: true,
  showHeatmap: true,
  heatmapIncrement: 5,     // +5% opacity per re-render
  fadeOutDuration: 2000,   // fade out over 2 seconds
  maxOpacity: 0.8,
});

// Or toggle at runtime
renderer.setDebugConfig({ showHeatmap: true });

// Get stats
const stats = renderer.getDebugStats();
// { totalRerenders, elementCount, avgRerenders }

// Reset tracking
renderer.resetDebugTracking();
```

### Custom Components

Each renderer owns a `ComponentRegistry`. Register a handler for an element type: `create(props)` builds the element, and the optional `applyProps(element, props)` runs with the element's props when it is created and when they change. Names are matched case-insensitively:

```typescript
renderer.getComponentRegistry().register("VideoPlayer", {
  create: () => {
    const video = document.createElement("video");
    video.controls = true;
    return video;
  },
  applyProps: (element, props) => {
    if (props.src !== undefined) (element as HTMLVideoElement).src = props.src;
  },
});
```

```hypen
VideoPlayer(src: "https://example.com/clip.mp4")
```

### Custom Applicators

An applicator handler is a function `(element, value) => void`, registered on the renderer's `ApplicatorRegistry`:

```typescript
renderer.getApplicatorRegistry().register("glow", (element, value) => {
  element.style.boxShadow = `0 0 ${value}px rgba(59, 130, 246, 0.5)`;
});
```

Then use it in your template:

```hypen
Text("Highlighted")
  .glow(10)
```

`ComponentRegistry` and `ApplicatorRegistry` are also exported from `@hypen-space/web` (and `@hypen-space/web/dom`), but a `new ComponentRegistry()` is not connected to any renderer; register on the renderer's own registries as shown.

## Canvas Renderer

For canvas-based rendering (games, data visualizations, pixel-perfect control):

```typescript
import { RemoteEngine } from "@hypen-space/core";
import { CanvasRenderer } from "@hypen-space/web/canvas";

const canvas = document.getElementById("canvas") as HTMLCanvasElement;
const remote = new RemoteEngine("ws://localhost:3000");

const renderer = new CanvasRenderer(canvas, remote, {
  devicePixelRatio: window.devicePixelRatio,
  backgroundColor: "#ffffff",
  enableAccessibility: true,
  enableHitTesting: true,
});

remote.onPatches((patches) => renderer.applyPatches(patches));
await remote.connect();
```

As with the DOM renderer, the second argument receives the user's actions.

Layout uses the `taffy-layout` WASM module. The renderer first requests `/taffy_wasm_bg.wasm` from the page's origin and falls back to jsDelivr and unpkg, so serve that file yourself to avoid a 404 and the CDN round-trip (`hypen build` copies it into `dist/`).

### Canvas Options

```typescript
interface CanvasRendererOptions {
  devicePixelRatio?: number;      // HiDPI support (default: window.devicePixelRatio)
  backgroundColor?: string;       // Canvas background color
  enableAccessibility?: boolean;  // Accessibility mirror for screen readers; also enables
                                  // keyboard focus and text-input editing
  enableHitTesting?: boolean;     // Click/tap detection on canvas elements
  safeAreaInsets?: Partial<SafeAreaInsets>; // Override the insets SafeArea pads by
  enableDirtyRects?: boolean;     // Only repaint changed regions
  enableLayerCaching?: boolean;   // Cache unchanged layers
  maxLayerCacheSize?: number;     // Max cached layers
  showLayoutBounds?: boolean;     // Debug: show element bounds
  showDirtyRects?: boolean;       // Debug: show repaint regions
  logPerformance?: boolean;       // Debug: log frame timings
}
```

### Canvas API

```typescript
renderer.applyPatches(patches);          // apply a patch batch
renderer.getNode("element-id");          // VirtualNode: { id, type, props, children, ... }
renderer.resize(800, 600);               // resize the canvas
renderer.setOptions({ showLayoutBounds: true });
renderer.registerPainter("Sparkline", (ctx, node) => { /* draw node */ });
renderer.clear();
renderer.destroy();                      // remove listeners and overlays
```

## Remote Apps

### Using the HypenApp Component

Embed a remote app inside a Hypen template:

```hypen
Column {
  Text("My App")
    .fontSize(24)

  HypenApp("ws://localhost:3000")
}
```

With options:

```hypen
HypenApp(
  url: "ws://localhost:3000",
  autoReconnect: true,
  reconnectInterval: 3000
)
```

Children with `.slot("loading")` and `.slot("error")` replace the built-in connecting and error views.

### RemoteEngine

`RemoteEngine` (from `@hypen-space/core`) is the WebSocket client used above:

| Method | Description |
|---|---|
| `connect()` | Open the connection and send `hello` |
| `disconnect()` / `dispose()` | Close it |
| `dispatchAction(name, payload?)` | Send an action to the server |
| `onPatches(cb)` | Patch batches to render |
| `onStateUpdate(cb)` | State snapshots from the server |
| `onConnect(cb)` / `onDisconnect(cb)` / `onError(cb)` | Connection events |
| `onSessionEstablished(cb)` | Fires for every new or resumed session; every session starts with a complete tree, so reset the renderer here if you reconnect |
| `getConnectionState()` / `getCurrentState()` / `getSessionId()` | Query |

Options: `autoReconnect`, `reconnectInterval` (ms), `maxReconnectAttempts`, `session` (for example `{ props: { platform: "web" } }`, sent in the `hello`).

## Browser WASM Engine

`@hypen-space/web-engine` runs the Rust engine in the browser, so a page can render Hypen DSL without a server:

```typescript
import { Engine } from "@hypen-space/web-engine";

const engine = new Engine();

// Default: loads the WASM from unpkg, pinned to the installed package version
// (DEFAULT_WASM_CDN_BASE)
await engine.init();

// Self-hosted: copy node_modules/@hypen-space/web-engine/wasm-browser/ to your site
await engine.init({
  jsUrl: "/hypen/hypen_engine.js",
  wasmUrl: "/hypen/hypen_engine_bg.wasm",
});
```

`hypen build` self-hosts these files for you. The server packages (`@hypen-space/server`) load their WASM automatically.

The engine provides low-level control over parsing and rendering:

```typescript
// Receive patches
engine.setRenderCallback((patches) => {
  renderer.applyPatches(patches);
});

// Set up the primary module
engine.setModule(
  "Counter",                        // module name
  ["increment", "decrement"],       // action names
  ["count"],                        // state keys
  { count: 0 },                     // initial state
);

// Render a Hypen DSL string
engine.renderSource(`
  Column {
    Text("Count: @{state.count}")
  }
`);

// Notify the engine of state changes
engine.updateStateSparse(
  null,                 // scope: null or "" = primary module, else a nested module's name
  ["count"],            // changed paths
  { count: 42 },        // new values, keyed by path
);

// Dispatch an action
engine.dispatchAction("increment", { step: 5 });

// Component resolution for imports
engine.setComponentResolver((name, contextPath) => {
  return { source: componentDSL, path: `/components/${name}` };
});

// Debug
engine.debugParseComponent(source);  // parsed AST as JSON
engine.getRevision();                // current render revision
engine.clearTree();                  // clear the render tree
```

### Legacy orchestrator (`Hypen`, `render`, `renderWithComponents`)

`@hypen-space/web-engine` also exports an older in-browser orchestrator: the `Hypen` class and the `render(name, selector, config?)` / `renderWithComponents(components, name, selector, config?)` helpers. It does **not** wire `Router` blocks automatically, register nested modules or route scoped `@actions.*`, so apps with routing or nested modules show no routes and their child-module actions fail. Use `hypen build` (which runs the same session code as `hypen dev` in a Worker) or a `RemoteServer` instead. The orchestrator is fine for a single flat module:

```typescript
import { app } from "@hypen-space/core";
import { renderWithComponents } from "@hypen-space/web-engine";

const counter = app
  .defineState({ count: 0 })
  .onAction("increment", ({ state }) => { state.count++; })
  .build();

await renderWithComponents(
  {
    Counter: {
      module: counter,
      template: `
        Column {
          Text("Count: @{state.count}")
          Button { Text("+") }.onClick(@actions.increment)
        }
      `,
    },
  },
  "Counter",
  "#app",
);
```

`HypenConfig` accepts `debug`, `wasmUrl`, `jsUrl`, `debugHeatmap`, `heatmapIncrement`, `heatmapFadeOut`, `componentsDir` and `loader`.

## Requirements

- A modern browser with WebAssembly and ES modules (only needed for the WASM engine and the canvas layout module; the DOM renderer with a `RemoteEngine` is plain JavaScript)
