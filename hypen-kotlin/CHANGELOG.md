# Changelog

All notable changes to `hypen-kotlin` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **Device Capability Protocol server plane (RFC 001, provisional) on the shared Rust broker.** On by default (see Changed); `HypenServer { allowedOrigins(…); authenticate { req -> … }; configureDevice { … } }` configures admission and tuning. New hello-driven connection API: `admit(UpgradeRequest)` (D1 upgrade admission: Origin allowlist when present, the app authenticator when absent, fail closed; 403 on refusal), `openConnection(key, HypenTransport)` (no hello grace, `helloTimeoutMs` → close 1008), `handleBinary(key, frame)`; `hello.device` is taken from its exact text and validated + negotiated by the Rust `deviceHandshake` (the reason is logged when the plane is disabled), `sessionAck` carries `device` and a rotating 256-bit `resumeToken` (`SessionManager.issueResumeToken` / constant-time `verifyResumeToken`; without it a known session id starts a new session), compression stays on (no context takeover in both directions, see Changed). Each device connection gets one Rust `DeviceBroker` (UniFFI) driven by `space.hypen.remote.device.DevicePlane` (ordered outbound queue with buffered-bytes reporting, one coroutine timer from `tick()`, consumer-paced credit; `core.capabilities` opens before any module callback; a broker close resets the socket with 1012). Handler API `DeviceContext` (`ctx.device` in action handlers, `context.device` in lifecycle callbacks): `supports`, `suspend request(Capability.X, params)` typed per capability (`UnaryCapability` / `JsonStreamCapability` / `BinaryStreamCapability`, closed `Permission` enum), `stream(…, onEvent|onData)`, cold `Flow`s `events(…)` / `data(…)`, `save(bytes, name, contentType)`, wrappers (`permissions`, `camera`, `mic`, `bluetooth`, `gallery`, `files`), Result-style `DeviceResult`, cancellation through coroutine cancellation, replay firewall (`BaseModuleInstance.runReplayed`), activation authority tied to `activate` / `deactivate` / `destroy`, background lifetime + pin cap through `DeviceServerConfig.revisionOverride` / `maxBackgroundOwners`. Cross-language e2e: `./gradlew deviceE2eTest` (the TS web client in bun over a real WebSocket).
- `HypenServer` now flushes patches produced outside a dispatch (e.g. a suspend handler's state change after awaiting) as their own `patch` message instead of dropping them.
- **Attach mode for the agent surface.** `HypenServer.attach(sessionId)` returns a non-owning `AgentHandle` over a live, handshake-completed client (`null` otherwise): `sessionId`, `isAlive`, `listActions()`, `suspend dispatch(name, payload)`, `getState(module, path)`, `revision()`, `manifest()`. `dispatch` goes through `NativeEngine.dispatchExternal` only, so the user's socket receives exactly the `patch` frame a click produces and `HypenEvents.actionDispatched` fires; a guard refusal throws `EngineError.ActionNotFound` with nothing sent and no revision bump. The handle never destroys, suspends or closes the session; once the client is gone every member throws `AgentSessionGoneException`. No authorization is performed — the caller is the authorizer. Also new: `NativeEngine.mcpManifest()`, `ExternalActions` (`NAVIGATE` / `BACK` / `SET_INPUT` = `hypen.navigate` / `hypen.back` / `hypen.set_input`).
- Drag-and-drop host support (`hypen-web/docs/dnd.md`). Every module instance now auto-registers the reserved outcome actions next to `__hypen_bind`: `__hypen_reorder {fromPath, from, toPath, to}` (or `{path, from, to}`) applies the engine's canonical `portable_path_move` through the new `ObservableState.move(fromPath, from, toPath, to)`, and `__hypen_pin {path, x, y, xKey?, yKey?}` writes both coordinates in one `ObservableState.update()` batch (missing intermediates auto-vivify, so reserved-mode boards create `__dnd.<group>.<key>`). Names and path helpers live in `HypenDnd`. Malformed payloads warn and no-op.
- `TypedHypenModuleBuilder.warnOnDroppedKeys` (default `true`): the typed DSL's `syncBack` now warns once per path when a key present in the state map is absent from the re-encoded data class (the `ignoreUnknownKeys` silent-wipe hazard, design §6.6). Top-level runtime-owned `__` keys such as `__dnd` are merged over, never replaced, and are not warned about.
- `-Phypen.jvmToolchain=<n>` Gradle property to run the build on a JDK other than the default 17. When no JDK 17 is installed and no toolchain auto-provisioning is configured, the build now falls back to the running JDK (17 or newer) while still emitting 17 bytecode (`-jvm-target 17` / `--release 17`) instead of failing at configuration time, so plain `./gradlew test` works on a JDK-21-only machine.
- `CompatibilityTest` now replays the `engine-compatibility-tests/fixtures/dnd/*.json` lowering fixtures (category `dnd`) through the real `NativeEngine` — the first Kotlin render-category runner — with the same patch-matching rules as the Rust runner; it is skipped (JUnit assumption) only when the native library is not built.
- `compression` option on the `HypenServer { … }` builder (default `true`) requesting WebSocket permessage-deflate (RFC 7692). Because `HypenServer` is transport-agnostic and never installs Ktor's `WebSockets` plugin, the flag is advisory: read `server.compression` where you install the plugin and add `extensions { install(WebSocketDeflateExtension) }`. See the README's "WebSocket transport" section and `example-server/src/main/kotlin/Sockets.kt`, which is now wired this way.

### Fixed
- **Remote UI wire shape (tester report: "malformed messages break Android updates and desktop rendering").** `patch` messages carried no `module` and `initialTree` no `state`. The Android renderer (Moshi) drops a `patch` without `module` whole — every UI update after the initial tree was lost — and the native desktop client (serde `RemoteMessage`) drops both, so nothing rendered. Both messages now carry the same members as the TS / Go servers (`initialTree {type, module, state, patches, revision, routes}`, `patch {type, module, patches, revision}`; attached-agent frames included); `initialTree.state` is the primary module's state with non-finite numbers sent as `null` (kotlinx would print a bare `NaN`, making the frame unparseable). Pinned by `RemoteWireConformanceTest` (a decoder with both clients' required members) and a device-connection case in `HypenServerDeviceTest`.
- **Resumed sessions get their state back.** A session resumed within its TTL (a network reconnect, or the reconnect after a hot reload) came back with the module's initial state unless the module defined `onReconnect` — and that handler is never given the saved state. Like the TS server's `triggerReconnect`, the saved state is now restored automatically when the module has no `onReconnect`; defining one still takes over the decision (`restore(...)` or not), with the same `ReconnectContext` as TS (which does not pass the saved state either). Under the auto-wired router the primary module's `location` is now written through the module's state (it went to the engine only, so saved state and `initialTree.state` always said `/`), and a restored `location` moves the router there before the tree renders, so the resumed session shows — and activates — the route it was on.
- **Actions after a route-table `navigate`.** Remounting destroyed the previous route's modules without removing their engine registrations, so the module mounted as the new primary was also still registered as a nested module and every one of its actions was refused as `ambiguous unscoped action`. The destroyed modules are now unregistered (a destroy site, as in `ManagedRouter.stop`) before the new route mounts.
- **No more `render` messages.** A route-table `navigate` and a `watchComponents` hot reload sent `{"type":"render",…}`, a type neither the Android nor the desktop client decodes (both dropped it, so the screen never changed). Hot reload now does what the TS server's `RemoteServer.reload()` does: every hello-driven socket is closed with 1012 (`HypenServer.RELOAD_CLOSE_CODE`, session kept), and the reconnect resumes the session into a new engine built from the changed sources, which sends a fresh `initialTree`. Route-table navigation (a Kotlin-only mode; the TS server navigates through its router, whose `router.push` answers with a `patch`) and hot reload on legacy `handleConnect` connections (no socket handle to close) send ONE ordinary `patch` that removes the top-level nodes the client holds and builds the new tree. The auto-wired router's `navigate` already answered with a `patch`. `RemoteWireConformanceTest` now covers every message type the server emits (`sessionAck`, `initialTree`, `patch`, `sessionExpired`) across navigation and hot reload, and fails on any unknown `type`.
- **One bad inbound message no longer ends the connection.** `handleMessage` threw whatever a dispatch threw — e.g. `HypenException.ActionException` for a renderer UI action on a node a re-render had just removed ("stale UI action target"), a malformed `__hypen_dispatch` envelope, or a failing handler — out of the host's `for (frame in incoming)` loop, which closed the socket and stopped every later update. Every message is now handled under a guard that logs and drops a failure (as the TS server does); nothing is sent and the revision does not move. A `hello` whose session setup fails closes the socket 1011 instead of leaving it half-initialised. A `navigate` to a path no route matches is ignored (it used to re-render the current template without remounting its module, leaving the engine without the module's action handlers).
- Device plane (RFC 001) on the default auto-wired router: the connection's device plane is attached — and `core.capabilities` opened — right after `sessionAck`, before any module is constructed or activated. The route module the auto-wired `ManagedRouter` activates while the session is established now gets a live `context.device` in `onCreated` / `onActivated` (it used to get a dead `device-disabled` one); route-mounted global contexts inherit the plane.
- `OutboundQueue` buffered bytes (what the device broker paces bulk frames against) count the UTF-8 wire size of queued text (not UTF-16 chars) and include the transport's own buffer through the new `HypenTransport.bufferedAmount()` (default `0`).

### Changed
- **Compression is on by default again, device plane or not — one message at a time.** `HypenServer.compression` follows `compression` in the builder (`Boolean`, default `true`) whether or not the device plane is on, and an explicit `compression = true` no longer turns the device plane off (the startup warning is gone). Device traffic may be compressed only with no context takeover in both directions (`server_no_context_takeover; client_no_context_takeover`), so device data never shares a compression history with other messages; clients keep a context-takeover socket UI-only. New `openConnection(key, transport, webSocketExtensions)`: the negotiated `Sec-WebSocket-Extensions` of the upgrade response — with context takeover in either direction a `hello.device` gets a UI-only session and one warning (`null` = not reported, the route vouches). The documented Ktor setup (README "Compression", `example-server`) installs the new example `HypenDeflate`, a wrapper around `WebSocketDeflateExtension` (`clientNoContextTakeOver = true`, `serverNoContextTakeOver = true`) that actually negotiates both parameters as a server — Ktor 3.1.1's own extension echoes only what the client offered (browsers and OkHttp offer neither) and writes parameters comma-separated; `HypenDeflateTest` (`./gradlew :example-server:test`) pins both against a real Ktor/Netty server.
- **Device access is on by default (RFC 001, provisional — no compatibility shims).** Every `HypenServer` negotiates a device plane for any client whose `hello` offers `device`; the `device { … }` builder switch is removed. Options move to `configureDevice { … }` (same `DeviceServerConfig`, same defaults; calls accumulate) and `disableDevice()` is the one opt-out (the old UI-only server). The server never refuses to start over device prerequisites: `allowedOrigins` / `authenticate` are enforced exactly when configured (an authenticator-only server now lets its authenticator decide requests that carry an Origin), and with neither configured every upgrade is admitted with ONE startup warning ("no allowedOrigins/authenticate configured — any client can connect; set them in production"). (Superseded: compression no longer interacts with the device plane — see the entry above.) Every `sessionAck` carries a rotating `resumeToken`; the token is required only to resume / kick-old-take-over a session that had a negotiated device plane (`SessionManager.markDeviceSession` / `requiresResumeToken`) — UI-only sessions keep id-only resume. `HypenServer.deviceEnabled` stays as read-only status.
- `HypenServer.handleConnect` (legacy, hello-less) works on every server again (it no longer throws): its sessions have no device plane, its ack carries a `resumeToken`, and an id belonging to a session that had a device plane starts a NEW session instead of resuming or taking it over.
- (Superseded by the entry above.) `HypenServer.handleConnect` (legacy, hello-less) now throws `IllegalStateException` on a device-enabled server (`device { }`) before touching any session: it has no resume credential, so it could resume a disconnected device session, or take over a live device connection under `KICK_OLD`, with the public session id alone. Use `admit` + `openConnection` (the example server and README now show this wiring). UI-only servers are unchanged.
- `HypenServer.handleMessage` no longer lets a deeply nested text crash the host: nesting is bounded by an iterative scan (256 containers) before the lenient parser runs, `StackOverflowError` is caught as a backstop, and device-typed texts it will not parse go to the broker (a counted connection-level violation, D4). A non-string `type` / `action` / `path` member is ignored instead of throwing.
- **BREAKING (provisional device protocol, `space.hypen.remote.device`, RFC 001):** the SDK no longer carries its own device protocol implementation. The Rust engine (reached through the UniFFI bindings) is the only decoder, validator and negotiator; the Kotlin strict-JSON tokenizer, envelope types (`DeviceMessage`, `DeviceRequest`/`Response`/`Event`, `Control`, `Owner`, `DeviceError`), handshake decoders and `selectDeviceAck`, `DeviceRegistry`, the schema interpreter (`DeviceValidation`, `DeviceSchemas`, bundled schema resources), the frame codec (`DeviceFrames`, `ChannelSeq`), `DevicePayloads`, `DeviceAdmission` and the `DeviceCapabilities` descriptors are removed. What remains (`DeviceTypes.kt`) are thin typed param classes (encoded with kotlinx; the broker validates them at open and refuses invalid ones with `invalidParams` naming the field) and result/event classes decoded with plain kotlinx from JSON the broker already validated, plus `Permission` / `DeviceErrorCode` / `Lifetime` and the other closed enums. `UnaryCapability` / `JsonStreamCapability` / `BinaryStreamCapability` expose `name` instead of `descriptor`. Conformance is replayed through the Rust broker: `DeviceBrokerTranscriptReplayTest` (every shared transcript, server role) and `DeviceBrokerConformanceTest` (selection, handshake, payload and envelope corpora).
- **BREAKING:** Removed `IconPack`, the `SvgParser` class, and the `.icons()` / `.iconsFromDir()` / `.iconFromFile()` builder methods. Use `resources(map)` / `resourcesDir(dir)` / `resourcesFile(path)` instead — they forward raw SVG strings to the Rust engine, which now owns all SVG parsing. The `Icon("name")` / `Icon(@resources.name)` DSL syntax is unchanged.
